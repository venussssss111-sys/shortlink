# 部署

## 一条命令

```bash
docker compose up -d --build
```

首次构建要拉 maven / node / nginx 镜像并下载依赖，**5~8 分钟**。之后改代码再跑同一条命令，只会重编受影响的那一层。

启动完访问 <http://localhost:8088>，账号 `admin` / `123456`（**仅本机演示**）。

> ⚠️ 公网部署前先从右上角头像改掉这个密码——它写在仓库里，不改等于公开管理员权限。

```bash
docker compose ps                 # 四个容器都应该是 Up / healthy
docker compose logs -f backend    # 后端日志
docker compose down               # 停（数据卷保留）
docker compose down -v            # 停 + 删数据
```

## 架构

```
                    ┌─────────────────────────────────────────┐
  浏览器 ────────▶  │  frontend (nginx:1.27-alpine)  :8088    │
  :8088             │                                         │
                    │  /              → Vue 打包产物（静态）   │
                    │  /api/**        → backend:8080          │
                    │  /uploads/**    → backend:8080          │
                    │  /V0002         → backend:8080（短链跳转）│
                    └────────────────┬────────────────────────┘
                                     │  只有这一个入口
                                     ▼
                    ┌─────────────────────────────────────────┐
                    │  backend (eclipse-temurin:17-jre) :8080 │
                    │  Spring Boot 3.3.5                      │
                    └──────┬──────────────────────┬───────────┘
                           │                      │
                  ┌────────▼────────┐    ┌────────▼────────┐
                  │ mysql:8.0       │    │ redis:7-alpine  │
                  │ :3306 (内部)    │    │ :6379 (内部)    │
                  │ volume: mysql-  │    │ volume: redis-  │
                  │ data            │    │ data            │
                  └─────────────────┘    └─────────────────┘
```

后端**不对外暴露端口**（只有 `expose`，没有 `ports`），所有流量必须经过 nginx。这不是洁癖，是三条实际的收益：

1. 只有一个入口，CORS 不需要开，安全策略只在一个地方维护；
2. 后端只能从内网被访问，数据库和 Redis 同理；
3. 换前端、加 CDN、上 HTTPS，都只动 nginx，后端不动。

## 三个不那么显然的点

### 1. 短码跳转为什么要单独一条 nginx 规则

短链的跳转地址是 `http://localhost:8088/V0002` —— **根路径下的单段**。

nginx 默认会把它当成静态文件去找 `/usr/share/nginx/html/V0002`，找不到就 404。所以必须用正则把「像短码的路径」转给后端：

```nginx
location ~ "^/(?!api|uploads|assets|favicon)[A-Za-z0-9]{4,10}$" {
    proxy_pass http://backend:8080;
}
```

那个负向断言 `(?!api|uploads|assets|favicon)` 是必须的：否则 `/assets` 本身（7 个字符，全是字母）也会被当成短码转发到后端。

### 2. 限流按 IP 计数，nginx 必须把真实 IP 传进来

`RateLimitInterceptor` 从 `X-Forwarded-For` 取客户端 IP。如果 nginx 没配 `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for`，后端看到的 `getRemoteAddr()` 全都是 nginx 容器的内网 IP（`172.x.x.x`）——

**结果就是全世界的用户共用一个令牌桶，一个人刷爆所有人。**

### 3. 健康检查接口必须免鉴权、免限流

`GET /api/health` 是给 Docker `HEALTHCHECK` 用的。它被 `@Valid` 之外的两个拦截器放行了：

- 免鉴权：探针拿不到 token；
- 免限流：探针每 15 秒一次，被限流拒绝 → 容器判定为不健康 → 被反复重启 → 越重启越糟。

这两个 `excludePathPatterns` 少写一个，表现都是「容器 Up 但一直 unhealthy」。

## 反代性能：一个 keepalive，2.5 倍吞吐

压测 500 并发时，第一版 nginx 只跑到 **6,237 QPS**，而且越跑越低（8,957 → 5,008），p99 234ms。

排查只用两步：

```bash
docker stats --no-stream            # nginx 1166% CPU（16 核里吃掉 11.6 核），backend 只有 156%
docker exec shortlink-app sh -c 'cat /proc/net/tcp | awk \'$4=="06"{n++}END{print n}\''   # 14,248 条 TIME_WAIT
```

TIME_WAIT 一万四千条 = nginx 每个请求都在和后端**新建一条 TCP 连接**。

原因：`proxy_pass` 用变量、`upstream` 又没写 `keepalive` 时，nginx 不复用后端连接；
每 1 万次请求就多 1 万次三次握手 + 1 万次 TIME_WAIT。

修法（本仓库 `frontend/nginx.conf` 已经是这样）：

```nginx
upstream shortlink_backend {
    zone shortlink_backend 64k;
    server backend:8080 resolve;   # 容器重建换 IP 也能自动跟上
    keepalive 128;
    keepalive_requests 10000;
}

location /api/ {
    proxy_pass http://shortlink_backend;
    proxy_http_version 1.1;
    proxy_set_header Connection "";   # 这两行是 keepalive 生效的前提
}
```

修完：**15,688 QPS（2.5 倍）、p99 62ms、吞吐从「衰减」变成「稳定」**。

> 一个容易忽略的点：`proxy_http_version` 默认是 1.0，而 keepalive 只在 1.1 下生效。
> 只加 `keepalive 128` 不加这两行，配置不报错但完全不生效。

## 镜像怎么变小的

后端用的是**两阶段构建**：

| 阶段 | 基础镜像 | 作用 | 大小 |
|---|---|---|---|
| 构建 | `maven:3.9-eclipse-temurin-17` | 编译、打 jar | ~700 MB（不进最终镜像） |
| 运行 | `eclipse-temurin:17-jre-alpine` | 只跑 jar | 429 MB（实测，其中 jar 43 MB + JRE 135 MB） |

前端同理：`node:20-alpine` 打包 → `nginx:1.27-alpine` 托管，最终镜像 **77 MB**。

最终镜像里**没有源码、没有 Maven、没有 `~/.m2`**，构建阶段那 700 MB 一层都不会进镜像。

配合两个细节：

- `COPY pom.xml` 单独一层 + `dependency:resolve`：只改代码时依赖层命中缓存，不用重新下依赖；
- `USER app`：非 root 运行。容器被攻破时，攻击者拿不到 root。

## 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 所有 `/api` 和短码跳转 502，首页正常 | `proxy_pass` 用了变量但没配 `resolver` | `nginx.conf` 里加 `resolver 127.0.0.11 valid=10s;`（日志会写 `no resolver defined to resolve backend`） |
| `shortlink-app` 一直 `unhealthy` | `/api/health` 被拦截器拦了 | 检查 `WebConfig` 里两个 `excludePathPatterns` |
| 打开页面白屏、`/api` 请求 502 | backend 还没起来 | `docker compose logs backend`，等它打印 `Started ShortLinkApplication` |
| 访问 `http://localhost:8088/V0002` 是 404 | nginx 少那条短码正则 | 看 `frontend/nginx.conf` 的 `location ~ "^/[A-Za-z0-9]{4,10}$"`（正则里的 `{}` 必须加引号） |
| 所有人都触发 429 | nginx 没传 `X-Forwarded-For` | 同上，检查 `proxy_set_header` |
| 数据库空表、没有 `user` 表 | 卷里已有旧数据，`initdb.d` 不会重跑 | `docker compose down -v` 重新初始化（会删数据） |
| 头像是裂图 | `uploads` 卷没挂上 | 确认 `backend` 服务有 `uploads:/app/uploads` |
| 构建卡在 `dependency:resolve` 很久不动 | 从 Maven Central 拉依赖，国内很慢（实测约 250 KB/s） | 见下面「构建太慢怎么办」 |
| 浏览器点登录 403，curl 却能登录 | 浏览器 POST 带 `Origin`，Spring 做 CORS 校验；把部署地址加进 `SHORTLINK_CORS_ALLOWED_ORIGINS` |

### 构建太慢怎么办

首次构建的大头是拉 Maven 依赖，不是编译。国内可以挂阿里云镜像，在 `Dockerfile` 的构建阶段加一行：

```dockerfile
COPY docker/maven-settings.xml /root/.m2/settings.xml
```

`docker/maven-settings.xml`：

```xml
<settings>
  <mirrors>
    <mirror>
      <id>aliyun</id>
      <mirrorOf>central</mirrorOf>
      <url>https://maven.aliyun.com/repository/public</url>
    </mirror>
  </mirrors>
</settings>
```

另一个实用技巧：**构建慢和构建卡住看起来一模一样**。看不见进度时用经典构建器，构建步骤会以普通容器出现，可以 `docker exec` 进去 `du -sh /root/.m2` 看依赖在不在增长：

```bash
DOCKER_BUILDKIT=0 docker build -t shortlink-backend . > build.log 2>&1
```

## 生产环境还差什么

这套是**能跑、能演示**的版本，不是生产级。真要上线还得补：

1. **HTTPS**：nginx 配证书，或前面再挂一层 SLB / CDN；
2. **密钥管理**：`SHORTLINK_JWT_SECRET` 和数据库密码走 secrets，不要写在 compose 里；
3. **日志**：现在打到 stdout，生产要接 ELK / Loki，并加 `traceId` 串起一次请求；
4. **监控**：Actuator + Prometheus + Grafana，JVM、连接池、慢 SQL；
5. **多实例**：后端无状态（session 在 Redis），可以直接 `--scale backend=3`，但**头像存本地磁盘会打架**，得换对象存储；
6. **数据库**：单机 MySQL 扛不住就上主从 + 读写分离，再往上分库分表。
