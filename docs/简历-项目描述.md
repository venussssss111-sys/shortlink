# 简历上的项目怎么写（可直接抄）

> 前提：所有数字都来自本仓库 `docs/压测报告.md`，被追问能当场复现。
> **没有数字的 bullet 一律不写**——"熟练使用 Redis" 这种句子只会让人问你八股。

## 一、项目名怎么写

不要写「短链接生成器」（一听就是教程复刻），也不要写「XXX 管理系统」。

推荐：

> **短链接服务（个人项目）** — 长链接转短链 + 跳转 + 访问统计，单机部署，含压测与性能优化

如果投的是偏业务的岗，可以换成：

> **营销短链与访问分析平台（个人项目）**

一句话定位（面试自我介绍用）：

> 一个自己从 0 写到能压测、能容器化部署的短链服务，重点做了缓存三防、布隆过滤、限流和访问统计，所有性能结论都有压测数据。

## 二、四条 bullet（按岗位取舍，最多写 4 条）

**① 核心链路 + 性能**

> 独立开发短链接服务（Spring Boot 3 + MyBatis-Plus + Redis + MySQL），实现短码生成、302 跳转、访问统计与限流；跳转链路采用 Cache-Aside + 空值缓存 + 随机 TTL 解决缓存穿透/击穿/雪崩，**压测 QPS 从 7,088 提升到 17,701、p99 从 37ms 降到 10ms，100 万次跳转仅产生 1 次数据库查询**。

**② 布隆过滤器（最能看出你会做取舍的一条）**

> 针对「随机短码打穿数据库」的问题引入布隆过滤器：先试 **Redis 版（Redisson）**，实测每请求 11 条 Redis 命令、QPS 反而降到 5,743，**判定为负收益后换成 Guava 本地布隆**，不存在的短码 QPS 从 6,713 提升到 18,781（2.8×），跳转路径 Redis 命令接近 0 条/请求。

**③ 访问统计（能体现异步/批量思维）**

> 访问统计做成「跳转路径零同步写库」：日志进有界队列（1 万容量、满则丢弃并计数），攒 200 条或 500ms 批量 INSERT；PV 走 Redis `INCRBY`、UV 走 `HyperLogLog`（12 KB 支撑亿级去重、误差 0.81%），定时任务聚合进 `link_stats` 并保证幂等（`ON DUPLICATE KEY UPDATE`）。

**④ 部署与压测（能体现实测精神）**

> 用 Docker Compose 一键部署 nginx / 后端 / MySQL / Redis 四容器，多阶段构建把后端镜像从 700 MB 压到 429 MB；**压测 500 并发时发现 nginx 未启用 upstream keep-alive、后端容器堆积 1.4 万 TIME_WAIT，修复后 QPS 6,237 → 15,688、p99 234ms → 62ms**。

**（可选）⑤ 安全**

> 手写 HS256 JWT + 拦截器 + ThreadLocal 上下文；基于 Redis 令牌桶（Lua 保证原子）按 IP/用户分级限流，超限返回 429 + `Retry-After`；登录注册接口单独设更严阈值。
> **并修复了一处越权（IDOR）**：短链加 `user_id` 归属 + 管理员标记编入 JWT，列表/改/删/详情/统计全部按用户隔离，越权统一返回 404 而非 403（避免靠状态码差异枚举全站短码）。

## 三、大概率被追问的 12 个问题（答案就一句话，别背长篇）

1. **短码为什么用随机 6 位，不用自增 ID？**
   自增可枚举，能被人爬全站链接；6 位 Base62 有 568 亿组合，够用到项目过期。
2. **302 还是 301？**
   302。301 会被浏览器永久缓存，同一用户再也不来服务器，统计全丢。
3. **缓存穿透怎么处理的？**
   查不到也缓存一个空值（30~60s 随机），再往前放了布隆过滤器挡随机码。
4. **空值缓存 TTL 为什么不设长一点？**
   它管的是「缓存说谎多久」：主动失效只覆盖正常路径，TTL 负责所有意外（删缓存失败、别人直接改库）。太长会让「补建的码」半天打不开，太短又没有保护效果。
5. **布隆为什么不用 Redis 版？**
   实测每请求 7 次 `GETBIT` + 脚本开销，QPS 从 16k 掉到 5.7k，负收益。本地布隆一次内存查询，误判率 1% 由业务兜底。
6. **布隆误判了怎么办？**
   误判 = 可能存在 → 继续查 Redis/MySQL → 查不到返回 404。只是多一次查询，不影响正确性。
7. **布隆里删了一个码怎么办？**
   布隆不支持删除（会把别的码一起"清"掉）。做法：删除时不动布隆，靠空值缓存兜底，重建时重新预热。
8. **日志为什么用队列不用线程池？**
   线程池任务再多也要一个个执行、内存不可控；有界队列满了可以**明确地丢**并计数，过载行为可预测。
9. **UV 为什么用 HyperLogLog？**
   精确去重要么存 SET（10 万 IP 就 5 MB）要么存表（每次都要 count distinct）。HLL 固定 12 KB、误差 0.81%，UV 这种指标不需要精确。
10. **限流为什么令牌桶，不是固定窗口？**
    固定窗口有临界问题：12:00:59 打 60 次 + 12:01:00 再打 60 次，2 秒内过了 120 次。令牌桶按时间连续补票，没有这个缝。
11. **JWT 是无状态的，怎么退出登录？**
    单机就存一个黑名单：`auth:black:{jti}`，TTL = token 剩余有效期。多实例也一样，只要 Redis 在。
12. **500 并发为什么只有 1.5 万？瓶颈在哪？**
    瓶颈是压测机自己（500 线程 × 28ms ≈ 1.78 万是理论天花板），服务端还没到顶。上一版真正的瓶颈是 nginx 没开 keepalive，那 1.4 万 TIME_WAIT 就是证据。

## 四、绝对不要写的话

| 别写 | 为什么 |
|---|---|
| 高并发、亿级流量 | 你没到那个量级，一问就露 |
| 微服务、分布式事务 | 这是单机单体，写上去就是在撒谎 |
| 熟练/精通 Redis、JVM 调优 | 没有对应的深度，必被八股打穿 |
| 日活 xx、服务 xx 用户 | 没有真实用户，编数字最致命 |
| 使用了 xx 中间件 | 用了不等于会，写"为什么用它"才有价值 |

## 五、语气上的两个技巧

- **主动说局限**：面试官问「这套东西有什么问题」时，答「单机部署、没做分库分表、统计是异步的会丢少量数据」，比硬吹加分得多。
- **把失败讲成判断**：Redis 布隆那一轮是失败的，但"试了、量了、判定负收益、换方案"这条链，比"一次就成功"更能证明你会做工程。
