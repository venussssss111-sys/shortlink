- [x] D2 Postman 调通 `POST /api/links`，拿到 shortUrl
- [x] D3 浏览器打开 shortUrl，确认 302 跳到原地址（F12 看 Network 状态码）

- [x] D4 调通 `GET /api/links`（分页）、`PATCH /api/links/{code}/status`、`DELETE`
- [ ] D4 故意传 `javascript:alert(1)`，确认被 `UrlValidator` 拒绝

## 第 2 周：缓存 + 防穿透 + 压测基线

目标：拿到 v1 和 v2 的压测对比数据。

- [x] JMeter 压 `GET /{code}`，**先压没有缓存的 v1**，记录 QPS / p99（这是基线，别跳过）
- [x] 加 Redis 缓存 `link:{code}`，TTL 1 小时
- [x] 加布隆过滤器：**先试 Redisson `RBloomFilter`，实测每请求 11 条 Redis 命令、真实码 QPS 17,728 → 5,743，是负收益**；
      改成 Guava 本地版（启动预热 + 每 60s 重建），Redis 命令降到 ≈0 条/请求
- [x] 加空值缓存（`link:{code}` = `""`，TTL 60s）
- [x] 加随机 TTL：真实码 1h ± 10%，空值 60s ± 15s，防雪崩
- [x] 热点 key 互斥重建（`SETNX lock:{code}` 或 Caffeine 本地锁）
- [x] 再压一次，出对比表：QPS / p99 / 缓存命中率 / 打库次数 → 完整数据见 [压测报告.md](压测报告.md)
- [ ] 写笔记：《布隆过滤器是怎么把无效请求挡在 Redis 之前的》

**过关标准**：压测报告里 v2 的 QPS 明显高于 v1，且不存在的短码在 SQL 日志里看不到查询。

## 第 3 周：访问统计

- [x] 跳转接口异步投递访问日志（实际用的是有界队列 `ArrayBlockingQueue` + 单线程消费者，满了丢弃并计数，比线程池更能扛突发）
- [x] 落 `access_log` 表（批量插入，别一条一条 insert）
- [x] UV 用 Redis HyperLogLog：`PFADD uv:{code}:{date} {ip}`
- [x] 定时任务：每天 00:05 把前一天的 Redis 计数写进 `link_stats`（也留了手动 `POST /api/stats/aggregate?date=`）
- [x] 接口：`GET /api/stats/link/{code}?days=7`（趋势 + 汇总）
- [ ] 接口：`GET /api/stats/{code}/sources`（Referer 分布）
- [x] 接口：`GET /api/stats/overview`（今日总 PV/UV、累计）+ `GET /api/stats/top?days=&limit=`（Top N）
- [ ] 写笔记：《为什么 UV 用 HyperLogLog 而不是 Set》

**过关标准**：手动点 100 次短链，看板接口返回 PV=100，UV 正确（同一 IP 只算 1）。

## 第 5 周：限流与安全

- [x] 登录鉴权：注册 / 登录 / 退出（Redis 黑名单记 jti）/ 改密码 / 上传头像（手写 HS256 JWT + 拦截器 + ThreadLocal）
- [x] 令牌桶限流（Redis + Lua，四个桶：read 60/5、write 20/1、create 10/0.5、auth 5/0.2）
- [x] 超限返回 429 + `Retry-After` 头（另带 `X-RateLimit-Remaining` / `X-RateLimit-Scope`）
- [x] 创建接口单独限流（`create` 桶，capacity 10 / rate 0.5，防刷短码）
- [x] URL 黑名单（非 http(s) 协议、`user:pass@` 写法、内网/回环/CGNAT/云元数据地址、非 80/443 端口、单段主机名）
- [x] 短码枚举防护（同一 IP 每分钟 404 超 30 次 → 429，`service/MissGuard.java`）
- [x] 写笔记：《令牌桶 vs 滑动窗口，我为什么选令牌桶》

**过关标准**：脚本快速刷 100 次，第 61 次开始返回 429。
